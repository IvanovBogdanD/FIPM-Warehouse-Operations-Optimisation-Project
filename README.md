# ФИПМ (Go / Wails)

Приложение включает главную страницу, каталог товаров, карточку товара, заказы и приёмку в интерфейсе AdminLTE. Основная SQLite-база `store.db` находится в корне репозитория и содержит 20 позиций: гвозди, саморезы, дюбели, молоток, кувалды, краски разных цветов, лаки по дереву, кисть, валик и грунтовку. Приложение открывает её в рабочем каталоге в режиме `rw`: оно не создаёт базу, таблицы или товары и не заполняет каталог автоматически.

## Возможности

- Главная `#home` открывается при запуске. Сумма остатков, количество позиций и список товаров с нулевым остатком загружаются из SQLite. Кнопка обновления повторно запрашивает данные.
- Данные брони, отгрузок и истории пока недоступны. Вместо вымышленных значений показаны пустые состояния, действия будущих модулей отключены.
- Каталог, поиск по полному названию и подстроке без учёта регистра (включая кириллицу), обновление без перезагрузки.
- Карточка `#product/<id>` показывает ID, название и количество из базы. Для остальных полей ТЗ, которых нет в схеме (фото, свободное количество, бронь, срок хранения и FIFO/LIFO, размеры, поставщик, SKU, идентификатор позиции, дата поступления), показано «Нет данных».
- Вкладка `#orders` показывает заказы со статусом, датами, ответственным и составом, поддерживает вкладки по статусам и поиск. Черновик можно отменить после подтверждения: заказ остаётся в списке со статусом «Отменён», остаток не меняется. Завершённую приёмку отменить нельзя.
- Кнопка «…» во вкладке заказов открывает меню: «Создать заказ» и «Приёмка товара». «Создать заказ» неактивен, пока не готов модуль №4.
- Добавление и удаление товаров запрещены. Старые методы `AddProduct` и `DeleteProduct` оставлены для совместимости, но возвращают ошибку.
- Приёмка открывается через «Заказы → троеточие → Приёмка товара». Черновик содержит товар, количество, ФИО и место хранения. Создание и отмена не меняют остаток; завершение атомарно увеличивает его. Повторное подтверждение не увеличивает остаток повторно.

Черновики и результаты заказов хранятся только в памяти Go до закрытия приложения. ФИО и место хранения не записываются в SQLite или отдельные файлы. После перезапуска остаются только изменённые остатки, постоянной истории приёмок нет.

## Ограничения существующей схемы

В исходном коде описана только таблица `products` с полями `id`, `name`, `count`. Артикулов нет, поэтому поиск выполняется только по названию. В карточке показаны ID, название и количество из базы. Фиксированный каталог не расширяется и не сокращается приложением. Товары уже находятся в основной базе `store.db`.

Таблиц заказов, статусов и брони в базе нет. Поэтому список заказов содержит только заказы на приёмку из памяти Go и очищается при закрытии приложения, дата отгрузки показывается прочерком, а отмена не снимает бронь и не записывает ничего в SQLite.

## Расположение файлов

```text
frontend/
  index.html                 точка входа HTML
  src/
    main.js                  подключение AdminLTE, Bootstrap и запуск приложения
    app/
      router.js              переходы между страницами
    layout/
      layout.html            общий каркас, шапка и боковое меню
      layout.js              подключение HTML страниц
    pages/
      home/
        home.html            главная страница
        home.js              загрузка показателей главной
      catalog/
        catalog.html         каталог и поиск
        catalog.js           загрузка списка товаров
        product.html         карточка товара
        product.js           загрузка карточки
      orders/
        orders.html          список заказов, состав, меню и окно отмены
        orders.js            загрузка, фильтры и отмена заказа
      receiving/
        receiving.html       форма и подтверждение приёмки
        receiving.js         создание, отмена и завершение
    shared/
      api.js                 обращения к Wails
      dom.js                 поиск элементов и показ сообщений
      icons.js               подстановка стандартных SVG в HTML
      icons/                 Bootstrap Icons и лицензия
      styles.css             правило для скрытия неактивных страниц
    api.js                   прежний путь импорта, перенаправляет в shared/api.js
    style.css                подключает общие стили
  tests/                     проверки интерфейса
db.go                        подключение SQLite
store.db                     основная база с 20 товарами
products.go                  существующие публичные методы товаров
orders.go                    список заказов и отмена
orders_test.go               проверки заказов на временных базах
receiving.go                 черновики в памяти и атомарная приёмка
receiving_test.go            проверки приёмки на временных базах
main.go                      запуск нативного окна Wails
warehouse_test.go            проверки SQLite и каталога
```

Каждая страница хранит разметку и логику в своей папке. Общий каркас и обращения к backend находятся отдельно. HTML подключается локально средствами Vite, сервер для выдачи шаблонов не нужен. Существующие Go-файлы и сигнатуры методов сохранены для совместимости.

Оформление использует готовые классы AdminLTE 4 и Bootstrap 5. Стандартные SVG взяты из [Bootstrap Icons 1.13.1](https://github.com/twbs/icons/tree/v1.13.1); лицензия MIT находится рядом с файлами. Дополнительных npm-зависимостей нет.

## Запуск и проверки

Нужны Go 1.26+, Node.js 20.19+ либо 22.12+, Wails v2.16 и системные зависимости Wails для выбранной платформы. AdminLTE 4 использует Bootstrap 5.3; Bootstrap объявлен прямой зависимостью. Новых библиотек бизнес-логики нет.

```sh
cd frontend
npm ci
npm test
npm run build
cd ..
go test ./...
go test -race ./...
go vet ./...
wails dev
```

`go test -race` требует cgo и C-компилятор. Нативная сборка выполняется командой `wails build`. На Linux с WebKitGTK 4.1 используйте `wails build -tags webkit2_41`.

`npm run dev` запускает Vite, но для получения реальных данных нужен Wails. В обычном браузере без backend показывается понятная ошибка. Frontend обращается к публичному `window.go.main.DBService`, поэтому отдельная генерация JS-файлов bindings для сборки Vite не требуется; Wails регистрирует сервис через существующий `Bind`.

Go-тесты создают отдельные временные базы с исходной схемой, не обращаются к рабочей `store.db` и не меняют её. Проверяются поиск, получение карточки, запрет изменения каталога, заказы и их отмена, ошибки SQLite и неизменность схемы. Frontend-тесты проверяют обращения к Wails, поиск, переход к карточке, вкладку заказов и окно отмены, запоздалые ответы, отображение ошибок и обработчики событий.
