# ФИПМ (Go / Wails)

Приложение включает главную страницу, каталог товаров, карточку товара, заказы, приёмку и инвентаризацию в интерфейсе AdminLTE. Основная SQLite-база `store.db` находится в корне репозитория и содержит 20 позиций: гвозди, саморезы, дюбели, молоток, кувалды, краски разных цветов, лаки по дереву, кисть, валик и грунтовку. Приложение открывает её в рабочем каталоге в режиме `rwc`. При отсутствии файла создаётся пустая база. Таблица `products` и товары автоматически не создаются; таблицы авторизации и инвентаризации инициализируются при запуске. Недостающие колонки характеристик добавляются прямо в `products`, отдельные таблицы для них не создаются.

## Возможности

- Главная `#home` открывается при запуске. Сумма остатков, количество позиций и список товаров с нулевым остатком загружаются из SQLite. Кнопка обновления повторно запрашивает данные.
- Главная также показывает свободный остаток, бронь, отгрузки на сегодня и ближайшие отгрузки. Они рассчитываются по текущим заказам. История действий пока недоступна.
- Каталог, поиск по названию, артикулу и SKU без учёта регистра (включая кириллицу), обновление без перезагрузки.
- Карточка `#product/<id>` показывает характеристики из `products`: ID, название, остаток, артикул, SKU, поставщика, производителя, склад, ячейку, даты поступления и окончания хранения, FIFO/LIFO, размеры, массу, объёмы и единицы в упаковке. Свободное количество и бронь рассчитываются по текущим заказам. Фотографии отсутствуют. FIFO/LIFO пока является характеристикой товара, учёта отдельных партий нет.
- Вкладка `#orders` показывает заказы со статусом, датами, ответственным и составом, поддерживает вкладки по статусам и поиск. Черновик приёмки и заказ в брони можно отменить после подтверждения: заказ остаётся в списке со статусом «Отменён», общий остаток не меняется, бронь снимается. Завершённый заказ отменить нельзя.
- Кнопка «…» во вкладке заказов открывает меню: «Создать заказ» и «Приёмка товара».
- Создание заказа `#orders/new` и `#orders/new/writeoff`: выбор товаров, количество, дата отгрузки или списания, адрес, ответственный, примечание. Количество помещается в бронь и вычитается из свободного остатка, общий остаток не меняется.
- Отгрузка и списание подтверждаются в карточке заказа: в одной транзакции SQLite уменьшается общий остаток всех позиций, бронь снимается. Повторно завершить заказ нельзя.
- Добавление и удаление товаров запрещены. Старые методы `AddProduct` и `DeleteProduct` оставлены для совместимости, но возвращают ошибку.
- Приёмка открывается через «Заказы → троеточие → Приёмка товара». Черновик содержит товар, количество, ФИО и место хранения. Создание и отмена не меняют остаток; завершение атомарно увеличивает его. Повторное подтверждение не увеличивает остаток повторно.
- Кладовщику доступна инвентаризация `#inventory`: выбор товаров, подсчёт, сверка и акт. Поиск раскрывается под полем и загружает по 10 позиций кнопкой «Ещё». Дата, ФИО, комиссия, тип проверки, фактические количества и комментарии сохраняются в SQLite. Остатки меняются после подтверждения корректировки. Сохранённый акт можно открыть повторно, скачать в PDF или открыть в системном просмотрщике для печати.

Черновики и результаты заказов хранятся только в памяти Go до закрытия приложения. ФИО и место хранения не записываются в SQLite или отдельные файлы. После перезапуска остаются только изменённые остатки, постоянной истории приёмок нет.

## Ограничения существующей схемы

Все характеристики товара хранятся в одной таблице `products`. Основная `store.db` содержит заполненные характеристики 20 товаров. Они сгенерированы для демонстрации и отмечены в карточке. Для красок, лаков и грунтовки указан срок хранения; для крепежа и инструмента срок не ограничен. Фиксированный каталог не расширяется и не сокращается приложением. ID, названия и остатки сохранены.

`product_schema.go` обновляет прежнюю схему при запуске. `data/products.json` содержит демонстрационные характеристики только для существующих ID и названий, не добавляет товары и не меняет количество. Повторный запуск сохраняет уже заполненные записи. Приложение читает данные из SQLite. Артикулы и ячейки также используются при выборе товаров, подсчёте, сверке и в акте инвентаризации, включая PDF.

Таблиц заказов, статусов и брони в базе нет. Поэтому заказы и бронь хранятся в памяти Go и пропадают при закрытии приложения: незавершённый заказ после перезапуска исчезает, а его бронь снимается. В SQLite записываются только изменения `count` при отгрузке, списании и приёмке. Клиенты и цены в этой версии не реализованы.

```text
        catalog.js           загрузка списка товаров
        product.html         карточка товара
        product.js           загрузка карточки
      orders/
        orders.html          список заказов, состав, меню и окно отмены
        orders.js            загрузка, фильтры, отгрузка, списание и отмена
      order-form/

        inventory.html       выбор, подсчёт, сверка, акт и подтверждение

        inventory-data.js    номер, дата и итоговые количества
        inventory-report.js  отображение и сохранение акта
        inventory-pdf.js     формирование PDF
    shared/
      api.js                 обращения к Wails
      dom.js                 поиск элементов и показ сообщений
      icons.js               подстановка стандартных SVG в HTML
      modal.js               открытие и закрытие окон Bootstrap из кода
      icons/                 Bootstrap Icons и лицензия
      styles.css             правило для скрытия неактивных страниц
    api.js                   прежний путь импорта, перенаправляет в shared/api.js
    style.css                подключает общие стили
  tests/                     проверки интерфейса
db.go                        подключение SQLite
store.db                     основная база с 20 товарами
products.go                  модель товара, каталог и поиск

warehouse_test.go            проверки SQLite и каталога
```

Каждая страница хранит разметку и логику в своей папке. Общий каркас и обращения к backend находятся отдельно. HTML подключается локально средствами Vite, сервер для выдачи шаблонов не нужен. Существующие Go-файлы и сигнатуры методов сохранены для совместимости.

Оформление использует готовые классы AdminLTE 4 и Bootstrap 5. Стандартные SVG взяты из [Bootstrap Icons 1.13.1](https://github.com/twbs/icons/tree/v1.13.1); лицензия MIT находится рядом с файлами. Для PDF используется [jsPDF](https://github.com/parallax/jsPDF). Шрифт Nunito с кириллицей и лицензией OFL включён локально.

## Запуск и проверки

Нужны Go 1.26+, Node.js 20.19+ либо 22.12+, Wails v2.16 и системные зависимости Wails для выбранной платформы. AdminLTE 4 использует Bootstrap 5.3; Bootstrap объявлен прямой зависимостью. Новых библиотек бизнес-логики нет.

```sh
cd frontend
npm ci
npm test
npm run build
cd ..
go test ./...
go test -race ./...
go vet ./...
wails dev
```

`go test -race` требует cgo и C-компилятор. Нативная сборка выполняется командой `wails build`. На Linux с WebKitGTK 4.1 используйте `wails build -tags webkit2_41`.

`npm run dev` запускает Vite, но для получения реальных данных нужен Wails. В обычном браузере без backend показывается понятная ошибка. Frontend обращается к публичному `window.go.main.DBService`, поэтому отдельная генерация JS-файлов bindings для сборки Vite не требуется; Wails регистрирует сервис через существующий `Bind`.

Go-тесты создают отдельные временные базы, проверяют обновление исходной схемы, не обращаются к рабочей `store.db` и не меняют её. Проверяются поиск, получение карточки, запрет изменения каталога, заказы и их отмена, бронь, отгрузка и списание, ошибки SQLite и сохранность характеристик при операциях с остатками. Frontend-тесты проверяют обращения к Wails, поиск, переход к карточке, вкладку заказов, форму заказа и окна подтверждения, запоздалые ответы, отображение ошибок и обработчики событий.
